# screen-cap

An open-source macOS screenshot app: capture (area, window, fullscreen, scrolling, timer),
annotate, OCR, pin and save, from the menu bar with global shortcuts. Screenshots, editing,
and saving only; screen recording is deliberately later. "Done" for v1 is every row marked
v1 in the feature matrix in `docs/PLAN.md`.

## Status
M1 in progress: app capture flow (issue #23) — overlays, window picker, shortcuts, save/copy. Last touched 2026-10-31.

## Pointers
- `docs/PLAN.md` — the build plan: feature matrix, architecture, milestones, acceptance.

## Commands
```bash
make build        # swift build (debug)
make test         # swift test; adds Swift Testing paths when only Command Line Tools are active
make bundle       # scripts/bundle.sh -> build/ScreenCap.app (release, ad-hoc signed, icon)
make run          # bundle, then relaunch build/ScreenCap.app
make lint         # swiftlint --strict
make clean
pkill -x ScreenCap                                   # quit a running build
# Optional, Xcode users only: xcodegen generate && open ScreenCap.xcodeproj
```

## Conventions & Gotchas
- Swift 6 strict concurrency. SwiftUI for windows and settings, AppKit for overlays,
  panels and the menu bar. Capture with ScreenCaptureKit only (no `CGWindowListCreateImage`).
- Logic lives in the `ScreenCapKit` Swift package so it can be unit-tested without the app.
- SwiftPM-first (overrides PLAN §8): the root `Package.swift` builds and tests everything with
  Command Line Tools alone, no Xcode. `project.yml` (XcodeGen) is a secondary path for Xcode
  users and is not verified in CI. Add ScreenCapKit files under its existing subfolders; no
  `Package.swift` edit needed. Use `make test`, not bare `swift test`, on a CLT-only Mac:
  bare `swift test` can't find the `Testing` module there. If Xcode is installed but its
  license isn't accepted, `export DEVELOPER_DIR=/Library/Developer/CommandLineTools`.
- The `.xcodeproj` is generated by XcodeGen from `project.yml`; never commit it.
- Global shortcuts use KeyboardShortcuts pinned to 1.x: every 2.x release has `#Preview`
  macros that Command Line Tools can't expand. Move to 2.x only if CI and local builds use Xcode.
- App-side logic tests live in `Tests/ScreenCapTests` (`@testable import ScreenCap`); keep that logic
  pure (no screen access) so it runs headless.
- Hidden launch options drive captures without key presses (CI smoke tests):
  `build/ScreenCap.app/Contents/MacOS/ScreenCap --capture <area|window|fullscreen|previousArea|selfTimer|allInOne|scrolling|text> [--action save|copy|overlay|annotate|pin] [--window <app>] [--quit]`.
  Launched from Terminal, Screen Recording permission is Terminal's.
- Original name, icon, UI, copy, backgrounds, and file format. Do not copy any other app's assets or branding.

## Out of Scope
- Screen recording, GIF, video editor, camera, keystroke and click overlays (later phase).
- Hosted cloud sharing, accounts, teams.
- Windows/Linux.
